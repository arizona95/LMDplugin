# kit-admin — 키트 운영을 말로

## 지금 상황 — 먼저 읽는다
- 관리자는 이 키트를 **잘 모른다**고 본다. 메뉴 이름·용어(감사자·개발감사·배포감사·레지스트리·조직 허용 목록 등)를 쓰면 한 문장으로 무엇인지 같이 말한다. 화면을 직접 열라고 하기보다 **내가 API 로 읽고 해서** 결과를 표로 보여 준다.
- 도우미: `bash "${CLAUDE_PLUGIN_ROOT}/scripts/kitadmin.sh"` (`KA`).
  - `KA api GET <경로>` — 읽기. 마음대로 부른다.
  - `KA api <POST|PUT|DELETE> <경로> '<JSON>'` — 쓰기. 먼저 `--yes` 없이 부르면 `KIT-API-CONFIRM` 으로 멈춘다. 관리자에게 **무엇이 바뀌는지 한 문장**으로 말하고 '예'를 받은 뒤 `--yes` 를 붙여 다시 부른다. 관리자가 이미 그 일을 분명히 시켰으면(예: "다 수락해줘") 대상 목록을 보여 주고 한 번만 확인받는다.
  - `KIT-LOGIN-NEEDED` 가 나오면: 관리자에게 **다른 터미널**에서 출력된 `bash … login` 을 한 번 실행하라고 한다(키트 주소·관리자 계정·비밀번호는 그 터미널에만 넣는다. 회사 SSO 로그인이면 사내 Git 에서 만든 토큰을 붙여 넣는 2번). 끝났다고 하면 이어서 한다. 비밀번호·토큰을 대화로 받지 않는다.
- API 목록: `references/api.md`(메뉴별 · 자동 생성). 메뉴·용어·배포 단계 설명: `references/menus.md`. 모르는 것은 추측하지 말고 API 로 읽어서 말한다.
- 키트가 막는 것은 우회하지 않는다: 자기가 올린 MCP 는 자기가 승인 못 함(다른 관리자) · 검사 '차단'·'오류' 는 승인 못 함(개발자 소명이 받아들여지면 됨) · 주관리자만 되는 설정.

## 자주 시키는 일
1. **"배포 요청한 거 뭐야 / 지금 배포 단계 뭐 있어"**
   - `KA api GET /api/requests` → 표: 시각 · MCP · 저장소 · 요청자 · 검사 결과(통과·검토·차단·오류·검사 중) · 걸린 항목 수 · 결정(대기·승인·반려).
   - '대기' 인 것은 무엇을 하면 되는지 한 줄씩(통과 → 승인하면 됨 · 검토 → 걸린 항목을 보고 판단 · 차단 → 승인 불가, 개발자 소명 대기 · 검사 중 → 기다림).
   - 배포 단계 전체를 물으면 `references/menus.md` 의 '배포 단계' 표로 설명하고, 지금 요청이 그중 어디에 있는지 짚는다.
2. **"이거 자세히 / 걸린 거 뭐야"** — `KA api GET /api/requests/<id>` → 걸린 항목마다 감사자 · 심각도 · 파일 · 한 줄 설명. 판단에 필요한 것(바깥 접속 주소 · 툴 목록 · 바뀐 툴)을 덧붙인다.
3. **"다 수락해줘 / 승인해줘"**
   - 대기 중인 것을 나눈다: 승인 가능(검사 끝 · 통과/검토 · 내가 올린 것 아님) / 불가(까닭). '검토' 는 걸린 항목을 한 줄씩 보여 준다.
   - 승인할 목록을 보여 주고 한 번 확인받은 뒤 하나씩 `KA api POST /api/requests/<id>/decision '{"action":"approve"}' --yes`. 반려는 `{"action":"reject","reason":"…"}`(사유 필수).
   - 결과 표(승인됨 · 실패와 까닭). 실패 메시지는 그대로 옮기고 무엇을 하면 되는지 말한다.
   - 이어서 4번(임직원에게 배포)을 바로 안내한다 — 승인만으로는 임직원 Claude 에 들어가지 않는다.
4. **"배포 네가 해줘 / 임직원이 쓰게 해줘 / 나 뭐 해야 돼"**
   - `KA api GET /api/registry` → 승인된 MCP · 버전 · 툴 · 마켓플레이스 동기화 상태 · `org_settings`(Claude 조직 관리형 설정에 넣을 값).
   - 키트가 저절로 하는 것(사내 마켓플레이스 갱신 · .mcpb/.zip 만들기)은 내가 확인해 결과만 말한다. 동기화가 실패했으면 `KA api POST /api/registry/sync '{}' --yes`(확인 뒤).
   - **관리자만 할 수 있는 것**(Claude 조직 설정 — 키트 밖 claude.ai 관리 화면)은 따라 하기 쉽게 번호로 준다: `org_settings` 값을 `~/kit-org-settings-<날짜>.json` 으로 저장하고, "Claude 조직 설정 → Claude Code → 관리형 설정 → [관리]" 를 안내한다. **관리형 설정은 그 조직의 모든 구성원 Claude Code 에 닿는다** — 먼저 관리자에게 지금 들어 있는 값을 복사해 보여 달라고 하고(또는 비어 있는지 묻고), 키트 값의 `allowedMcpServers`·`allowManagedMcpServersOnly`·`extraKnownMarketplaces` 만 바꾸고 나머지 키는 그대로 둔 **합친 파일**을 만들어 준다. `allowManagedMcpServersOnly: true` 는 목록 밖 MCP 를 모두 막는다는 뜻이라는 것도 말한다. 관리자가 붙여 넣은 뒤 [설정 업데이트]. 데스크톱 확장으로도 줄 거면 '커넥터 → 추가 → 사용자 지정 → 데스크톱 → .mcpb 올리기 → 팀에 추가'(파일은 `GET /api/registry` 의 resources 에 나온 이름으로 `KA download /admin/registry/<이름>/resources/<파일> ~/<파일>`).
   - 마지막에 "임직원은 Claude 를 다시 켜면 됩니다 — 마켓플레이스 플러그인을 처음 쓰는 PC 는 사용자 설치 매뉴얼"이라고 말한다. 관리자가 붙여 넣었다고 하면 다시 `GET /api/registry` 로 지금 승인 목록과 붙인 값이 맞는지 본다(버전이 바뀌면 다시 붙여야 한다는 것도).
5. **"자동승인 켜줘 / 꺼줘"** — `KA api GET /api/approval` 로 지금 방식을 보고, `KA api PUT /api/approval '{"mode":"auto"}'`(끄기는 `"manual"`, 주관리자만). 자동이면 CI·배포감사 '통과'인 요청을 키트가 바로 승인해 사내 마켓플레이스(local-mcp-dev-marketplace)에 올린다 — 관리자 자기 MCP 도 승인되므로 켜기 전에 그 점을 한 문장으로 말하고 확인받는다. 켠 뒤 들어온 요청부터 적용, '검토'·'차단'·'오류' 는 대기에 남는다.
6. **"이 메뉴 뭐야 / 뭐 할 수 있어"** — `references/menus.md` 로 그 메뉴를 설명하고, 그 메뉴의 API 로 지금 값을 읽어 함께 보여 준다(예: 백업 → `GET /api/backup` · 서버 외부 접속 → `GET /api/egress`).
7. **"개발자 오류 보여줘 / 사내 PC 에서 뭐가 안 돼?"** — 개발자 PC 의 개발 플러그인은 명령이 실패하면 그 명령 · 출력 그대로 · PC 상태(OS · Node · git · 프록시 · 플러그인 판 · 워크스페이스 · 마지막 개발감사)를 키트에 보낸다.
   - `KA api GET '/api/devkit/reports?limit=50'` → 표: 시각 · 계정(로그인 전이면 빈칸) · 명령 · 실패 줄 · OS · 플러그인 판. 같은 실패 줄끼리 묶어 몇 건인지.
   - 자세히: `KA api GET /api/devkit/reports/<id>` → 출력 전체와 상태를 읽고 원인을 한두 문장으로(개발자 쪽 설정 문제인지 · 키트·플러그인 결함인지). 개발자가 할 일이면 그 사람에게 전할 문장을 만들어 준다.
   - "회사 인증서 1024비트 PC 몇 대야": 실패 줄이 `회사 TLS 검사 인증서 키가 2048비트보다 짧음 — 호환 모드` 인 기록을 PC(host)별로 센다. 그 PC 는 개발 플러그인이 그 PC 에서만 OpenSSL 보안 수준 1 로 접속해 쓰고 있다(인증서 확인은 그대로). 고칠 곳은 회사 IT — TLS 검사(Somansa 등) 루트 인증서를 2048비트 이상으로 바꿔 달라고 요청할 문장과 PC 목록을 만들어 준다.
   - 키트·플러그인 결함으로 보이면 `KA pull-reports ~/kit-devpc-reports` 로 모아 두고, "키트를 고치는 쪽에 이 폴더를 넘기면 된다"고 말한다.
8. **설정 바꾸기**(외부 접속 열기 · 감사자 켜기 · 관리자 지정 · 백업 지금 · 복원 시험 · 배포 거둬들이기 등) — api.md 에서 맞는 API 를 찾아, 바뀌는 것을 말하고 확인받은 뒤 부른다. 바꾼 뒤 같은 GET 으로 결과를 다시 읽어 보여 준다.

## 하지 않는 것
- 확인 없이 쓰기 API 를 부르지 않는다. 회수(revoke) · 관리자 해제 · 퇴사 처리 · 로그 지우기 · 버전 설치는 관리자가 그 대상을 분명히 말했을 때만, 결과를 한 번 더 말하고 부른다.
- 키트의 검사 판정을 바꾸지 않는다(오탐이라 생각하면 개발자 소명 → 관리자 판단 절차를 안내).
- 토큰 파일(`~/.config/mcp-kit-admin/token`)·비밀값을 출력하지 않는다.
