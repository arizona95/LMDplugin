# 키트 메뉴 · 용어 · 배포 단계 (관리자에게 설명할 때)

## 한 줄로
사내 MCP 개발 키트 = 임직원이 만든 MCP 를 **검사하고, 관리자가 승인한 것만** 회사 Claude 에 넣는 서버. 사내 Git · 검사기(감사자) · CI · 포털이 한 서버(쿠버네티스)에 있다.

## 배포 단계 (개발자 → 임직원)
| 단계 | 누가 | 무엇 | 포털에서 보이는 곳 |
|---|---|---|---|
| 1 개발 | 개발자(자기 Claude) | 개발 플러그인으로 MCP 를 만들고 이 PC 에서 직접 띄워 툴을 불러 본다 | - |
| 2 개발감사 | 키트 | 커밋마다 바뀐 파일만 SkillSpector 로 검사. 통과한 커밋만 개발자가 시험할 수 있다 | - |
| 3 배포 요청 | 개발자 | "배포해줘" → 사내 CI(빌드·툴 목록·테스트) 결과 확인 → 검사 요청 | 'MCP 등록' 요청 목록(결정 = 대기) |
| 4 배포감사 | 키트 | 저장소 전체를 감사자들(SkillSpector · 의존성 취약점 osv · 격리 실행 · LLM 감사자)이 검사 → 통과 / 검토 / 차단 / 오류 | 요청 목록 '검사' 칸 · 걸린 항목 |
| 5 승인 | 관리자(요청자 아닌 사람) | 통과·검토는 승인 가능, 차단·오류는 불가(개발자 소명이 받아들여지면 가능). 반려는 사유 필수 | 요청 목록 '결정' |
| 6 배포 자원 | 키트(저절로) | 승인하면 사내 마켓플레이스 갱신 · Claude Desktop 확장(.mcpb) · 다른 클라이언트 묶음(.zip) · 조직 관리형 설정 값(org_settings) 생성 | '레지스트리' |
| 7 조직 설정 | 관리자(claude.ai 관리 화면) | 조직 관리형 설정에 org_settings 를 통째로 붙여 넣기(필수 — 안 하면 임직원 세션에서 그 MCP 가 조용히 빠짐) · 원하면 커넥터에 .mcpb 올리고 '팀에 추가' | 키트 밖 |
| 8 사용 | 임직원 | Claude 를 다시 켜면 들어온다(마켓플레이스 플러그인을 처음 쓰는 PC 는 사용자 설치 매뉴얼대로 설치) | '에이전트 실행'(실행 기록) |
| 새 버전 | 개발자 → 관리자 | 3~7 을 다시. 새 버전을 승인하면 옛 버전은 바로 멈추므로 7 을 바로 한다 | - |
| 거둬들이기 | 관리자 | '레지스트리'에서 회수(사유) → 임직원 PC 에서 다음 실행부터 막힘 | - |

| 묶음 | 메뉴 | 무엇 |
|---|---|---|
| 개발 | 신규 개발 | 개발자가 새 MCP 저장소를 만드는 곳 |
| 개발 | MCP 등록 | 검사 요청 목록(모든 개발자의 요청 · 검사 결과 · 결정). 관리자는 여기서 승인·반려 |
| 개발 | 다운로드 | 개발자 PC 설치 명령·시험 도구 |
| 개발 | Git | 사내 Git(Gitea) — 저장소·계정 |
| 배포 | 레지스트리 | 승인된 MCP 목록 · 배포 자원(.mcpb/.zip) · 마켓플레이스 상태 · 조직 관리형 설정 값 · 회수 |
| 배포 | 자산 현황 | 게시자별 MCP 이력(요청·결과·결정자) |
| 배포 | 에이전트 실행 | 임직원 PC 에서 배포된 MCP 가 뜬 기록 · 실행 인증 방식 |
| 검사·통제 | 감사자 | 배포감사에 쓰는 검사기 목록(켜기·끄기·막는 수준) |
| 검사·통제 | LLM 차단 패턴 | 서버 LLM 게이트웨이로 나가는 내용에서 막을 정규식 |
| 검사·통제 | 서버 외부 접속 | 키트 서버가 바깥으로 나갈 수 있는 주소 허용 목록(기본 차단) · 접속 기록 · 검증 |
| 검사·통제 | 개발자 PC 정책 | 개발자 시험 도구가 실행마다 받는 정책(비밀값 출처 등) |
| 운영 | 모니터링 | 요청·검사·LLM 사용량·바깥 연결 차단 등 숫자 |
| 운영 | 백업·복구 | 매일 암호화 백업 · 정기 복원 시험 · 지금 백업 · 보관 개수. 저장 위치가 같은 디스크면 서버를 잃을 때 함께 잃는다(서버 밖 NFS·SMB 권장) |
| 운영(주관리자) | 회사 환경 | 인증서 · LLM · 회사 프록시 · SSO · SIEM · 개발 플러그인 zip 받기 → '적용하고 다시 시작' |
| 운영(주관리자) | 계정·접근 | 관리자 지정·해제 · 접속 허용 IP · 퇴사·직무 변경 회수 · SCIM |
| 운영(주관리자) | 버전 관리 | 지금 키트 판과 구성요소 · 새 묶음 올려 설치 |

## 용어
- **개발감사** — 개발 중 커밋마다 바뀐 파일만 보는 빠른 검사. **배포감사** — 배포 요청 때 저장소 전체를 보는 검사 + 관리자 승인.
- **감사자(watcher)** — 배포감사의 검사기 하나하나. 결과는 통과 / 검토(사람이 보고 판단) / 차단(승인 불가).
- **소명(appeal)** — 개발자가 걸린 항목이 오탐이라고 적는 것. 다른 관리자가 받아들이면 그 항목은 막지 않는다.
- **레지스트리** — 승인된 MCP 와 그 판·툴·해시의 목록. 임직원 PC 는 여기 있는 것만 받는다.
- **조직 관리형 설정(org_settings)** — Claude 조직이 임직원 Claude Code 에 내려보내는 설정. 키트는 승인된 MCP 의 실행 명령을 글자 그대로 넣은 값을 만든다. 한 글자라도 다르면 그 MCP 는 빠진다.
- **주관리자 / 관리자** — 주관리자 = 설치 때 만든 kitadmin(또는 SSO 관리자 그룹). 관리자 = 주관리자가 지정한 사람(승인·반려·조회).
